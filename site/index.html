How it works

A stake, a challenge, a ruling.

Kleros Curate holds the list and the money. GenLayer validators make the one decision code cannot make.

01 · LIST

Publisher stakes

A skill is listed at one exact commit, so its content can never change, with a deposit.

02 · CHALLENGE

Hunter quotes a line

Anyone can challenge by quoting the passage they say is malicious, with a matching deposit.

03 · JUDGE

Validators read the file

Each validator fetches the file, confirms the quote is in it, and answers one question about that passage.

04 · PAY

Curate pays the winner

Malicious: the skill is rejected and the hunter is paid. Benign: it is listed and the publisher is paid.

Use it

Give your agent the skill

The Authena skill tells an agent to check the list before installing any other skill.

git clone https://github.com/Leokings/authena
cd authena && npm install

# exit code 0 only if that exact version is listed
npx tsx scripts/authena.ts check \
  <owner/repo> <commit> <folder>
# list a version, or challenge one (Sepolia test ETH)
npx tsx scripts/authena.ts list <owner/repo> <commit> <folder>
npx tsx scripts/authena.ts challenge <owner/repo> <commit> \
  <folder> SKILL.md "<the passage>"

What counts as malicious

  • Sending secrets, keys or private files anywhere
  • Moving or approving funds
  • Ignoring the user, or hiding actions from them
  • Downloading and running remote code

…when the skill's own stated purpose does not require it.

Limits

  • One listing covers one commit.
  • The judge reads the quoted passage, not the whole repository, and does not run code.
  • Rulings are carried between chains by one relay key.
  • Test networks only.
